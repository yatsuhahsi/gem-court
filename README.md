# GEM COURT — ファイル分割版（試作版）

**発展カード・貴族の情報とゲーム本体を別ファイルに整理したバージョンです。**
元の試作版のゲームルールや処理は変更していません。原作ベース（15点、カード90枚、予約3枚）＋各ターン基本20秒・個人持ち時間180秒の仕様です。

## ファイル一覧

| ファイル | 役割 | 主に編集する場面 |
|---|---|---|
| `index.html` | 画面の入口とファイルの読み込み | 画面構成の調整 |
| `style.css` | 色・サイズ・PC/スマホのレイアウト | UIの見た目を変更するとき |
| `cards.js` | 発展カード90枚（Lv.1=40、Lv.2=30、Lv.3=20） | カードの価格、得点、割引色の確認・変更 |
| `nobles.js` | 貴族10枚（3点、獲得条件） | 貴族の情報を確認・変更するとき |
| `game.js` | ターン進行・購入・予約・描画・Firebase同期 | ゲームロジックを変更するとき |
| `firebase-config.js` | Firebase Webアプリの接続設定 | Firebaseを接続するとき |
| `database.rules.json` | テスト用Realtime Databaseルール | Firebaseのルール画面に貼り付ける |

**重要：実際にゲームが読み込むカードデータは `cards.js` と `nobles.js` です。**

## 遊び方

1. ZIPを**展開**し、各ファイルを同じフォルダーに置いてください。
2. `index.html` を開き、「この端末でテスト対戦」を選びます（同一端末で2人分を交互に操作）。
3. カードデータを変更するときは `cards.js`、貴族データは `nobles.js` を編集します。保存後にページを再読み込みすると反映されます（新規対局を開始してください）。

`index.html` だけを別のフォルダーに移動すると読み込めなくなります。**同じフォルダー構成を維持してください。**

## GitHub Pagesで公開する場合

1. 新しいGitHubリポジトリを作り、上記のファイルを**まとめてリポジトリの最上位**にアップロードします。
2. `Settings → Pages` で `Deploy from a branch / main / (root)` を設定します。
3. `firebase-config.js` に新規FirebaseプロジェクトのWebアプリ設定値を入力します。
4. Firebaseの **Authentication → ログイン方法 → 匿名** を有効化し、Realtime Databaseルールに `database.rules.json` の内容を設定します。
5. GitHub Pagesの公開URLを別々の端末・ブラウザから開いて、ルーム作成・参加を試します。

Firebaseは前作Quantumgomokuと**別プロジェクト**を用意することを推奨します（異なるデータ構造を扱うため）。Firebase接続用の具体的なキー値は、この配布ファイルに記入されていません。

## テスト版の注意点

- ローカルでのルール処理や画面の動作は確認していますが、実際のFirebaseを使った複数端末でのオンライン対戦は未検証です。
- `database.rules.json` は**友人同士の試験用**です。参加者が悪意をもってデータを書き換える行為への防御や予約カードの秘匿は保証できません。公開運用ではCloud Functions等のサーバー側検証が必要です。
- 自動削除や切断判定の一部は接続中のブラウザに依存します。誰も接続していない状態での確実な削除にはサーバー側処理が必要です。
- カードデータの数値は公開されている非公式実装を参照した試作データで、原作現物と最終照合したものではありません。
- 予約・購入・貴族獲得などの既存動作を維持した**構造整理版**です。UIや細部は今後変更できます。
